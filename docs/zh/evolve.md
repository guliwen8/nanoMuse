# 回看（自进化）

nanoMuse 会写技能、也会记事——但两件事都得**你开口**。「以后都按这个来」是一次请求，「把它存下来」是另一次请求。你不说话，它就不会变。

回看是另一半：一轮任务结束之后，它自己回头看一遍，问「这次有什么值得留下」，然后把值得的东西**提出来给你看**。

```
一轮任务结束
   └─► 回看（后台，一次模型调用）
          ├─► 技能：一个做对的活儿，带上让它做对的那几个细节
          ├─► 记忆：路上顺口告诉它的一件长期事实
          └─► 一条消息：要不要存下来？
                    └─► 你说「存」──► 它用 skills / remember 存
                                          └─► 照例弹一次审批给你确认
```

## 两种值得留下的东西

| | 是什么 | 例子 |
|---|---|---|
| **技能**（skill） | 一个做对的、或者你演示过的、以后还会再做的活儿。写清楚让它做对的那几个细节：哪个账号、什么格式、什么限制、哪种说法 | 「发朋友圈：配 3 张图，正文不超过 60 字，发布前先把文案给我看」 |
| **记忆**（memory） | 关于你的一个长期事实：你希望事情怎么做、你的偏好、一个名字、一个账号、你给过的一条规矩 | 「小红书主账号是『柠檬不加冰』」 |

## 底线：每一条提案都得能指着自己的出处 {#ground-rule}

模型提议，模块裁决。这是回看唯一重要的一条：

> **每一条提案都必须带一句从对话里原样抄出来的 `quote`，模块会去对话里找这句话。找不到，这条提案就被丢掉。**

所以它不能凭空端出一条你没说过的话——引不出来，就不算数。除此之外还要过：

- 技能名得像个名字（小写、连字符、≤64 字符）
- 技能得有描述、有步骤
- 已经有的技能不再提一遍；已经记着的事实不再提一遍
- 一次最多留 3 条技能、3 条记忆

被丢掉的原因会记下来，不是悄悄丢掉。

## 它不会自己写任何东西 {#nothing-written}

回看只产出**提案**，一个字都不写。

写是下一步的事，而且走的是本来就在的两条路：`skills`（存技能）和 `remember`（记事）。这两条路都是 `sensitive` 级——哨兵会弹审批卡片给你看（[哨兵](sentinel.md)）。所以真正落盘的顺序是：

1. 回看提出来 → 一条消息
2. 你回「存」 → 它调用 `skills` / `remember`
3. 哨兵弹审批 → 你确认
4. 才真的写进去

**一个能在没人看着的情况下改自己的智能体，是另一个东西，而且更糟。** 这个功能要的是「你教一次，它记住，以后自己会用」，不是「它自己决定自己是谁」。

## 什么时候会回看 {#when}

- **一轮前台对话结束，而且这一轮把活儿干完了**（模型调用了 `terminate`）。没干完的（撞了步数上限、出错、停在提问上）没有「做完的活儿」可学。
- **后台的活儿不回看**：例程、目标的检查——它们没有跟你说话，也就不该打断你。
- 你正在说下一句的时候也不插话：提案会等下一轮结束再说。

## 关掉它 {#off}

```toml
[agent]
self_review = false
```

默认是开的。每轮结束多一次短的模型调用（读一遍对话、产出提案），不改任何东西。

## 和「手动让它记住」的区别 {#versus-asking}

| | 手动 | 回看 |
|---|---|---|
| 触发 | 你说「记住这个做法」 | 一轮任务结束时自动 |
| 写什么 | 你说的那些 | 对话里**做对的**那部分，和**顺口说过的**事实 |
| 谁裁决 | 你 | 模型提议，模块按上面的规则裁决 |
| 落盘 | 你说存 → 审批 | 一样：提案 → 你说存 → 审批 |

回看不会替你决定「这个值得记住」——它只是把候选摆出来，并且保证每一个候选都指得出它是从哪句话来的。

代码：`nanomuse/evolve.py`（引擎）、`nanomuse/server/service.py` 的 `_look_back()`（什么时候回看）。测试：`tests/test_evolve.py`。
